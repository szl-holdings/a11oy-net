Truth boundary

What this room proves—and what it does not.

A serious diligence surface makes its non-claims as visible as its evidence.

What can be inspected

  • Versioned public source, history, checks, and release records.
  • Receipt-verification entry points and published assurance evidence.
  • Public benchmark implementations and schemas.
  • Point-in-time public Hugging Face listing metadata.
  • The static proof site’s own reachability and committed contract.

What is not implied

  • A link or HTTP response is not proof of capability, quality, or uptime.
  • This site’s reachability is not product-runtime readiness.
  • Public Hub metadata is not an authenticated private inventory.
  • A runtime stage is transport metadata, not end-to-end promotion.
  • No financial, customer, safety, or performance claim is created here.

Known boundaries

Risks stay in the room.

Architecture boundaries are versioned; runtime and edge-deployment states remain point-in-time and require source-bound observation.

SEPARATE RUNTIME

Product availability can differ

The product domain and this static evidence domain have different deployment and failure modes. Live DNS for a11oy.net is GitHub Pages. Product code may 301 .net to .com only if that Host is routed into the product app. This origin is not a product host.

PUBLIC METADATA

Registry reads are bounded

Hub listing APIs report public metadata only and may be partial, unavailable, or rate limited.

EDGE UNKNOWN

Header deployment remains unverified

The repository contains an edge-header contract, but this candidate carries no source-bound live readback URI, UTC time, or source revision. GitHub Pages does not apply _headers; do not claim enforcement until a bound readback succeeds.
